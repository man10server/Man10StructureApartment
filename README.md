# Man10StructureApartment

プレイヤーごとに個室のアパートを貸し出す Paper プラグイン。各部屋はストラクチャとして保存・復元され、利用料は Vault 経済から日割りで徴収します。

## 仕組み

建築用ワールドの一直線上(`Y=100`, `Z=0`)に、`X = 部屋番号 × Distance` の間隔で部屋を並べて配置します。部屋はプレイヤーが入居するときに動的に設置され、ログアウト時にストラクチャとして保存されます。

部屋のスロットは**所有者がオンラインの部屋だけ**を数えて確保されます。そのため `MaxApartCount` は「同時に部屋を開ける人数」の上限であり、登録できる住民数の上限ではありません。オフラインになった部屋のスロットは次の入居者に再利用され、その際ワールド上の建物は上書きされます(ストラクチャは保存済みなので、次回入居時にファイルから復元されます)。

プレイヤーは部屋の鉄のドアを右クリックするか、メニューのボタンから出入りします。

## 動作環境

| 項目 | バージョン |
| --- | --- |
| Minecraft (Paper) | 1.21.8 |
| Java (サーバー) | 21 以上 |
| 必須プラグイン | Vault と、それに対応する経済プラグイン |
| 任意プラグイン | Man10CommonLibs |

## ビルド

```
./gradlew build
```

生成物は `build/libs/` に出力されます。Gradle ラッパー(9.7.0)を使うため Gradle の個別インストールは不要です。ビルドに使う JDK は 21〜26 が利用できます。出力されるバイトコードは JDK のバージョンによらず Java 21 ターゲットに固定されています。

## 導入

1. ビルドした jar を `plugins/` に置いてサーバーを起動する(初回起動で `plugins/Man10StructureApartment/config.yml` が生成される)。
2. `config.yml` を設定し、サーバーを再起動するか `/msa reload` を実行する。
3. 初期建築 `Apart/Default` を用意する(下記参照)。

### 初期建築の用意

新規入居者には `plugins/Man10StructureApartment/Apart/Default` が複製されます。**このファイルが無いと誰も入居できません。**

建築用ワールドに雛形の部屋を建て、バニラのストラクチャブロックで保存したファイルを `Apart/Default` という名前で配置してください。雛形には出入り口として鉄のドアを設置します。プレイヤーはこれを右クリックして元の場所へ戻ります。

## 設定 (config.yml)

| キー | 説明 |
| --- | --- |
| `BuilderWorld` | 部屋を配置するワールド名 |
| `Distance` | 部屋どうしの X 方向の間隔(ブロック)。部屋の幅より大きくする |
| `MaxApartCount` | 同時に開ける部屋数の上限 |
| `DailyRent` | 1 日あたりの利用料。メニューには 30 日分の金額が表示される |
| `BackCommand` | 部屋から出るときにプレイヤーが実行するコマンド(スポーンへ戻すコマンドなど)。先頭の `/` は不要 |
| `RelativeX` | 部屋の原点から見たテレポート先の相対 X 座標 |
| `RelativeY` | 同上、相対 Y 座標 |
| `RelativeZ` | 同上、相対 Z 座標 |

`RelativeX` / `RelativeY` / `RelativeZ` は、部屋の中の立ち位置(ドアの前など)を指すように設定します。すべて 0 のままだと部屋の隅(ストラクチャの原点)に転送されます。

## コマンド

| コマンド | 説明 |
| --- | --- |
| `/msa` | メニューを開く |
| `/msa jump` | 自分の部屋へテレポートする。部屋にいるときは `BackCommand` で戻る |
| `/msa pay <日数>` | 指定日数ぶんの利用料を支払う。利用可能期間が残っているうちは支払えない |

以下は `man10apart.op` 権限が必要です。

| コマンド | 説明 |
| --- | --- |
| `/msa reload` | 設定を再読み込みする |
| `/msa place <uuid>` | 指定プレイヤーの部屋を自分の現在地に設置する |
| `/msa save <uuid>` | 指定プレイヤーの部屋を保存し、住所情報から削除する。建物自体は手動で撤去する |
| `/msa backup <uuid>` | 直近 20 件のバックアップを一覧表示する。クリックでその時点へ復元できる |
| `/msa restore <uuid> <番号>` | 指定した番号のバックアップへ復元する |

`/msa place` と `/msa save` は、管理者が部屋の中身を確認・修正するための組み合わせです。`place` で手元に呼び出し、修正後に `save` で書き戻します。

## アパート内の建築制限

部屋の範囲内では**シュルカーボックスの設置と破壊だけ**が許可されます。それ以外のブロックは設置も破壊もできず、バケツによる液体の設置・回収も禁止されます。判定には住所情報 (`Address.json`) に登録された範囲を使うため、`/msa place` で管理者の手元に呼び出した部屋も対象です。

`man10apart.op` 権限を持つプレイヤーはこの制限を受けません。雛形の修正や部屋の手直しはこの権限で行ってください。

## 入居から退去までの流れ

### 新規入居

履歴のないプレイヤーが `/msa pay` を実行すると、部屋の確保と利用料の支払いがまとめて行われます。あとは `/msa jump` でテレポートできます。

```
/msa pay 30  →  部屋を確保し、利用料を支払う
/msa jump    →  部屋へテレポート
```

部屋を確保していない状態で先に `/msa jump` を実行した場合も、その場で部屋が確保されます。ただし確保直後の支払期限は「現在時刻」なので、利用料を支払うまではテレポートできません。

部屋の確保時には、空きスロットの決定 → `Apart/Default`(または既存の `Apart/<uuid>`)の読み込み → 対象範囲のブロック削除 → ストラクチャ設置 → 住所情報の登録、という順で処理されます。

### 利用料の支払い

**利用可能期間が残っているうちは支払いできません。** メニューのボタンを連打しても二重に徴収されることはなく、期限が切れるまで支払いは拒否されます。

支払えるのは期限が切れてからで、延長は現在時刻を起点に指定日数ぶん行われます。滞納しても部屋は消えないため、期限切れのまま放置しても中身は保持されます(下記「退去・削除」参照)。

部屋を確保した直後は期限が「確保時刻」なので、そのまま支払いに進めます。

### 保存

部屋の中身がファイルに書き出されるのは次のタイミングです。プレイヤーが部屋にいる間の編集は、これらを経てはじめて保存されます。

- ログアウト時
- 利用料の支払い成功時
- サーバー停止時
- `/msa save <uuid>` の実行時

支払期限はストラクチャファイル自体にも埋め込まれるため、住所情報が失われても期限は復元されます。

### 退去・削除

明示的な退去コマンドはありません。消えるタイミングは対象ごとに異なります。

| 対象 | 消えるタイミング |
| --- | --- |
| ワールド上の建物 | 次の入居者がその座標スロットを取ったとき(上書き) |
| 住所情報 (`Address.json`) | 同じ座標が再利用されたとき、`/msa save`、`/msa restore` |
| ストラクチャファイル (`Apart/<uuid>`) | 自動削除されない |
| バックアップ | 自動削除されない |

利用料を滞納した場合はテレポートができなくなるだけで、部屋の中身は保持されます。期限内に支払えばそのまま利用を再開できます。

## データの保存場所

いずれも `plugins/Man10StructureApartment/` 以下です。

| パス | 内容 |
| --- | --- |
| `Address.json` | 誰がどの座標の部屋を使っているか、および支払期限 |
| `Apart/Default` | 新規入居者に複製される初期建築 |
| `Apart/<uuid>` | 各プレイヤーの部屋のストラクチャ |
| `Apart/backup/<uuid>/<日時>` | 保存・呼び出しのたびに作られるバックアップ |

ストラクチャファイルとバックアップは自動削除されないため、長期運用では古いものを定期的に整理してください。
